# 모바일 실사용 UX 개선 설계·검증 계획

2026-10-13. 상태: 코드 조사 후 설계 검토 대기. 구현·실기기 검증 완료 기록이 아니다.

## 사용자 목표

iOS에서 현재 위치 또는 주소로 내 차량이 사용할 충전소를 찾고, 결과에서 이용 조건을 이해한 뒤 최소 단계로 길찾기를 시작한다. 기능별 PR·필수 CI·보호된 자동 머지를 순차 진행한다. 브랜치와 worktree는 feat/·fix/·refactor/ 등 작업 목적 이름을 사용한다. 병렬 에이전트 실행은 포함하지 않는다.

## 현재 코드에서 확인한 문제

- useCurrentLocation은 매 요청마다 geolocation을 다시 호출한다. 영구적인 거부 캐시는 없다. iOS 설정 변경 후에도 실패한 원인은 실기기·접속 origin·보안 컨텍스트·OS와 사이트 권한 확인 전 확정할 수 없다. 예외별 안내가 예시 위치로 집중된다.
- StationSearchView는 운영 화면에 합성 예시 위치를 노출한다. 지도와 검색 조건이 결과보다 먼저 나오고 수집 안내도 첫 결과 앞에 길게 나온다.
- selectPlace는 좌표만 바꾼다. 지도 표시와 주변 검색은 별도 행동이다.
- SearchForm은 차량 대신 커넥터를 직접 요구한다. 선택 표시 점의 생성은 폭 변동 가능성이 있으나 실제 애니메이션 원인은 재현이 필요하다.
- T32는 커뮤니티 조사만 완료했다. 차량/개인 어댑터 카탈로그 및 합집합 호환 검색은 없다. 커뮤니티 경험담으로 차량 호환이나 개인 보유를 자동 추정하지 않는다.
- StationCard는 지도 선택/상세 이동을 제공한다. StationDirections는 상세 안의 접힌 details여서 길찾기 단계가 길다.
- ChargerList는 원본 코드·삭제 표시·빈 비고·원본 시각을 일반 사용자 정보와 같은 비중으로 표시한다.
- 공급자 statUpdDt는 상태 변경 시각이다. sourceObservedAt과 collectedAt을 대체할 수 없다. 관측 시각 미제공은 수집 실패와 다르다.

## 선택한 방향과 대안

추천은 기존 목록·지도·API를 유지하고 기능별로 사용자 경로를 개선하는 방식이다. 문구만 수정하면 차량 계약과 길찾기 단계 문제가 남는다. 지도 전면 재작성은 변경 범위가 커지므로 현재 목적에 필요하지 않다.

```text
현재 위치 / 주소 후보 선택 → 검색 기준 위치 확정 → 주변 결과
                                            ├─ 목록 카드 → 길찾기
                                            └─ 지도 마커 → 하단 선택 패널 → 길찾기
내 차량 + 이번에 사용할 어댑터 → 검증된 호환 규격 → 중복 없는 검색
공급자 상태·이용 조건 → 사용자 판단 요약 → 필요한 경우 원본 정보 펼치기
```

## 기능별 실행 순서와 완료 조건

### T38 — 현재 위치 복구와 운영 데모 제거

브랜치 fix/ios-location-recovery. secure context·API 미지원·권한 거부·위치 불가·timeout을 구분한다. iOS 권한을 코드로 강제 허용하지 않는다. 권한 변경 후 재요청, 늦은 callback 무시, 중복 요청 취소를 유지한다. 실패 시 주소 검색을 직접 제시한다. 운영 예시 위치 버튼을 제거하고 테스트는 위치/주소 경계 fixture로 구성한다. 개발 데모가 필요하면 명시적인 개발 전용 경로로 격리한다.

Red: 실패 유형별 안내·재시도 성공·운영 예시 미노출. Green 후 전체 프런트·타입/lint/build·공용 verify. cmux 브라우저 성공/거부/주소 복구와 iOS 실기기의 설정 변경→복귀→재시도는 구분한다. 실기기가 없으면 iOS 해결 완료로 표시하지 않는다.

### T39 — 결과 우선 검색과 주소·지도 동기화

브랜치 feat/search-results-first. 검색 전에는 짧은 위치/차량 입력, 검색 후에는 조건 요약과 결과를 우선한다. 조건 수정은 펼칠 수 있게 한다. 주소 후보 선택 시 지도에 선택 위치를 표시하고 선택 차량 조건으로 주변 검색한다. 목록과 지도는 같은 확정 검색 조건을 공유하고 이전 응답이 새 결과를 덮지 못하게 한다. 지도 이동 후 재검색은 명시적 버튼을 유지한다. 수집 세부 안내는 요약 뒤에 접는다.

Red: 주소 선택→지도 중심/검색 요청 일치, 응답 역전·주소 실패·빈 결과·지도 실패 시 목록 유지. 320/375px에서 첫 결과가 긴 안내 아래로 밀리지 않는 브라우저 assertion을 추가한다. CSS 순서만 뒤집어 키보드 순서와 화면을 다르게 만들지 않는다.

### T40 — 목록·지도 하단 패널에서 바로 길찾기

브랜치 feat/station-quick-directions. 목록 카드에서 길찾기, 마커 선택 시 하단 패널에 충전소 이름·호환 상태·이용 조건 요약과 길찾기/상세를 표시한다. 첫 길찾기는 하단 앱 선택 패널, 선택한 앱은 이 기기의 선호로 기억해 다음에는 직접 연결하고 변경 동작을 제공한다. 상세 진입과 dropdown은 필수 단계에서 제거한다.

Red: 카드/마커의 정확한 목적지, 앱 최초 선택/재사용/변경, 패널 닫기·초점 복원·선택 대상 교체, 잘못된 좌표·저장소 접근 실패·앱 미설치 안내. 기존 OS별 URL 계약과 웹 대안을 유지한다. 브라우저의 링크 검증과 실제 iOS 앱 실행을 구분한다.

### T41 — 이용 조건·상태 시각을 이해할 수 있는 상세

브랜치 feat/charging-information-summary. 상태·내 차량 호환·운영 시간·출입 조건을 우선한다. Y만 있거나 모호한 문구뿐이면 ‘이용 대상·출입 조건 확인 필요’로 표시하고 확인된 구체 조건은 그대로 보여 준다. 근거 없이 이용 가능/금지를 단정하지 않는다. 원본 코드·삭제 표시·기술 식별자·수집 시각은 ‘정보 출처’ 안으로 옮기고 빈 비고는 생략한다.

관측 시각이 없으면 현장 확인 시각을 제공하지 않는다고 설명한다. 수집 시각은 서버 갱신이며 빈자리 확인이 아님을 짧게 설명한다. 원본 상태 변경 시각은 의미/형식이 유효한 경우에만 읽기 쉽게 표시하며 시간대 미확인 표시를 유지한다. 최신성 판정에는 임의 사용하지 않는다.

Red: 제한 Y/N/누락·구체/모호한 조건·빈 비고·미제공/깨진/미래 시각·원본 펼치기. API 원본 보존과 기존 최신성/추천 정책을 변경하지 않고 표현 책임을 presentation 모듈에 둔다.

### T42 — 차량·현재 사용할 어댑터 기반 호환 검색 (기존 T32 구현)

브랜치 feat/vehicle-compatibility. 검증 가능한 국내 차량부터 제조사·모델·연식/시장별 카탈로그를 구성하고 공식 제조사 근거·확인일을 기록한다. 확인되지 않은 차종은 ‘차량 정보 없음/직접 규격 설정’ 경로를 제공한다. 어댑터는 미확인/없음/검증된 모델을 구분하며 보유와 현재 사용 선택을 구분한다. 단순 ‘어댑터 있음’으로 규격 전체를 허용하지 않는다.

차량 프로필은 입력/저장을, 호환 정책은 직접/어댑터/확인 필요 판단을, API는 다중 규격 전달을, Repository는 호환 필터 후 limit와 중복 없는 대수를 소유한다. 검색·상세 복귀·추천·공유 URL까지 동일 계약을 적용하고 기존 단일 connector URL은 호환한다. 선택 표시 공간을 고정해 내용 이동을 없애며 reduced motion을 반영한다.

Red: 동일 차량의 어댑터 없음/휴대 안 함/사용 선택, 미지원 조합·연식/시장 미확인·다중 규격 충전기 중복·필터 후 limit·추천 일치·이전 URL. 공식 자료가 부족하면 그 차종의 호환을 만들어 넣지 않는다. 전체 Java·프런트·HTTP/REST Docs·MySQL·개발/배포 브라우저를 검증한다.

## 전달과 기록

각 기능은 테스트 assertion 실패 확인→최소 구현→전체 검증→이름/책임/공개 계약 리뷰→서명 commit/push→PR→현재 head 필수 CI→보호 확인 후 native auto-merge→실제 main 반영 확인 순서다. 현 main CI의 CD 활성 여부를 확인하고 자동 배포 효과는 별도 권한과 구분한다.

로컬 E2E 전에 호출 CMUX_WORKSPACE_ID/CMUX_SURFACE_ID와 cmux identify를 확인하고 같은 workspace의 보조 터미널/브라우저를 재사용한다. 로그·실제 assertion·종료 코드·보고서와 실기기 한계를 기능별 기록에 남긴다. 계획 작성만으로 완료 체크하지 않는다.
